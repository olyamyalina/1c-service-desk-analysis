# 14. Тестовые сценарии

## 1. Статусы проверки

| Статус | Значение |
|---|---|
| Проверено | Сценарий был выполнен вручную, результат зафиксирован |
| Подготовлен | Ожидаемый результат выведен из текущего кода, но запуск ещё не подтверждён |

Наличие программной проверки не считается успешным тестом. Если сценарий выполнен, в таблице нужно заменить статус и добавить дату, использованные данные и фактический результат.

## 2. Минимальные тестовые данные

Перед прогоном создать:

- активного сотрудника-заявителя, связанного с пользователем информационной базы;
- активного сотрудника-исполнителя с признаком `МожетБытьИсполнителем`;
- руководителя с признаком `ЯвляетсяРуководителемIT`;
- ответственного за оборудование с соответствующим признаком;
- категории с включённым и выключенным признаком `ТребуетОборудование`;
- приоритеты `Низкий`, `Средний`, `Высокий`;
- положительные правила SLA для каждого используемого приоритета;
- проблемное оборудование, закреплённое за заявителем и находящееся в состоянии `Используется`;
- свободное оборудование без истории состояний: оно должно считаться находящимся на складе.

Всем прикладным пользователям назначается роль `БазовыеПраваServiceDesk` и необходимая функциональная роль.
