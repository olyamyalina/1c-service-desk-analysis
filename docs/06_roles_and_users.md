# 06. Роли пользователей и права доступа

## 1. Назначение раздела

Данный раздел описывает роли пользователей системы «1С Service Desk», их основные задачи, доступные действия и ограничения доступа.

Раздел нужен для того, чтобы определить, какие категории пользователей будут работать с системой, какие функции им доступны и какие данные они могут просматривать или изменять.

Описание ролей используется при дальнейшем формировании функциональных требований, use case диаграммы, тест-кейсов и модели объектов 1С.

## 2. Общая логика разграничения доступа

В системе «1С Service Desk» доступ пользователей должен зависеть от их роли.

Разграничение доступа необходимо для того, чтобы:

1. сотрудник видел только свои заявки;
2. IT-специалист работал с назначенными ему заявками;
3. руководитель IT-отдела мог контролировать весь процесс;
4. ответственный за оборудование мог вести учёт техники;
5. администратор мог настраивать систему, но не подменял бизнес-процесс обработки заявок.

Основной принцип разграничения доступа:

> пользователь должен иметь доступ только к тем функциям и данным, которые нужны ему для выполнения своих задач.

## 3. Роли пользователей системы

В системе выделяются следующие роли:

1. сотрудник;
2. IT-специалист;
3. руководитель IT-отдела;
4. ответственный за оборудование;
5. администратор системы.

## 4. Роль «Сотрудник»

### 4.1. Описание роли

Сотрудник является заявителем. Он создаёт IT-заявки при возникновении проблемы, отслеживает статус своих обращений, предоставляет уточнения и подтверждает результат выполнения.

### 4.2. Основные задачи сотрудника

Сотрудник должен иметь возможность:

1. создать IT-заявку;
2. указать категорию обращения;
3. описать проблему;
4. прикрепить информацию об оборудовании, если проблема связана с устройством;
5. просматривать список своих заявок;
6. отслеживать статус своих заявок;
7. предоставлять уточнения по запросу IT-специалиста;
8. проверять результат выполнения;
9. подтвердить закрытие заявки;
10. вернуть заявку в работу, если проблема не решена.

### 4.3. Доступные данные

Сотрудник имеет доступ:

- к своим созданным заявкам;
- к статусам своих заявок;
- к комментариям по своим заявкам;
- к результатам выполнения своих заявок;
- к оборудованию, закреплённому за ним, если это предусмотрено системой.

### 4.4. Ограничения доступа

Сотрудник не должен иметь возможность:

- просматривать все заявки компании;
- изменять исполнителя заявки;
- изменять SLA;
- изменять приоритет после регистрации, если это право не предусмотрено;
- закрывать заявки других сотрудников;
- просматривать управленческие отчёты;
- изменять справочники системы;
- изменять настройки ролей и прав доступа.

## 5. Роль «IT-специалист»

### 5.1. Описание роли

IT-специалист является исполнителем заявки. Он получает назначенные заявки, берёт их в работу, анализирует проблему, запрашивает уточнения, выполняет действия по решению проблемы и фиксирует результат.

### 5.2. Основные задачи IT-специалиста

IT-специалист должен иметь возможность:

1. просматривать назначенные ему заявки;
2. брать заявку в работу;
3. просматривать описание проблемы;
4. просматривать информацию о заявителе;
5. запрашивать уточнение у сотрудника;
6. добавлять комментарии по заявке;
7. указывать оборудование, связанное с заявкой;
8. выполнять действия по решению проблемы;
9. указывать результат выполнения;
10. переводить заявку в статус «Решена»;
11. возвращать заявку к анализу при необходимости.

### 5.3. Доступные данные

IT-специалист имеет доступ:

- к назначенным ему заявкам;
- к заявкам своей группы, если это предусмотрено настройками;
- к информации о заявителе;
- к категории, приоритету и SLA заявки;
- к истории изменений назначенной заявки;
- к оборудованию, связанному с заявкой.

### 5.4. Ограничения доступа

IT-специалист не должен иметь возможность:

- изменять настройки SLA;
- изменять роли пользователей;
- удалять заявки;
- просматривать административные настройки системы;
- изменять системные справочники без отдельного права;
- закрывать заявку от имени сотрудника без подтверждения результата.

## 6. Роль «Руководитель IT-отдела»

### 6.1. Описание роли

Руководитель IT-отдела контролирует работу IT-службы, просматривает все заявки, отслеживает нарушения SLA, анализирует загрузку специалистов и принимает управленческие решения.

### 6.2. Основные задачи руководителя IT-отдела

Руководитель должен иметь возможность:

1. просматривать все IT-заявки;
2. контролировать просроченные заявки;
3. просматривать нарушения SLA;
4. анализировать загрузку IT-специалистов;
5. просматривать отчёты по статусам заявок;
6. просматривать отчёты по категориям заявок;
7. просматривать отчёты по среднему времени решения;
8. перераспределять заявки между специалистами;
9. изменять исполнителя заявки;
10. контролировать критические обращения.

### 6.3. Доступные данные

Руководитель IT-отдела имеет доступ:

- ко всем заявкам;
- к истории изменений заявок;
- к нарушениям SLA;
- к отчётам по заявкам;
- к отчётам по исполнителям;
- к отчётам по просрочкам;
- к информации об оборудовании, если она связана с заявками.

### 6.4. Ограничения доступа

Руководитель IT-отдела не должен иметь возможность:

- изменять технические настройки конфигурации;
- изменять роли пользователей;
- удалять системные данные;
- выполнять административные действия без роли администратора.

## 7. Роль «Ответственный за оборудование»

### 7.1. Описание роли

Ответственный за оборудование ведёт информацию о технике, закреплённой за сотрудниками компании, а также фиксирует состояние оборудования, ремонты, возвраты и списания.

### 7.2. Основные задачи ответственного за оборудование

Ответственный за оборудование должен иметь возможность:

1. просматривать список оборудования;
2. добавлять новое оборудование;
3. изменять карточку оборудования;
4. фиксировать закрепление оборудования за сотрудником;
5. фиксировать возврат оборудования;
6. указывать состояние оборудования;
7. фиксировать отправку оборудования в ремонт;
8. просматривать историю ремонтов;
9. просматривать заявки, связанные с конкретным оборудованием;
10. формировать отчёты по оборудованию.

### 7.3. Доступные данные

Ответственный за оборудование имеет доступ:

- к справочнику оборудования;
- к типам оборудования;
- к моделям оборудования;
- к состояниям оборудования;
- к истории ремонтов;
- к заявкам, связанным с оборудованием;
- к отчётам по оборудованию.

### 7.4. Ограничения доступа

Ответственный за оборудование не должен иметь возможность:

- изменять заявки, не связанные с оборудованием;
- менять исполнителя IT-заявки;
- изменять SLA;
- управлять ролями пользователей;
- изменять административные настройки системы.

## 8. Роль «Администратор системы»

### 8.1. Описание роли

Администратор системы отвечает за настройку системы, пользователей, ролей, справочников и параметров работы 1С Service Desk.

### 8.2. Основные задачи администратора системы

Администратор должен иметь возможность:

1. управлять пользователями;
2. назначать роли пользователям;
3. настраивать справочники;
4. настраивать категории заявок;
5. настраивать приоритеты;
6. настраивать правила SLA;
7. управлять параметрами системы;
8. контролировать корректность справочной информации;
9. выполнять техническое сопровождение системы.

### 8.3. Доступные данные

Администратор системы имеет доступ:

- к настройкам системы;
- к пользователям;
- к ролям;
- к справочникам;
- к параметрам SLA;
- к служебным объектам системы.

### 8.4. Ограничения доступа

Администратор системы не должен использовать административные права для подмены бизнес-действий пользователей без необходимости.

Например, администратор не должен закрывать заявку от имени сотрудника или менять результат выполнения заявки без служебного основания.

## 10. Связь ролей с будущими объектами 1С

В 1С роли пользователей будут использоваться для ограничения доступа к объектам конфигурации.

Предварительное соответствие ролей проекта ролям 1С:

| Роль в проекте | Возможная роль в 1С |
|---|---|
| Сотрудник | ПользовательСотрудник |
| IT-специалист | ИсполнительЗаявок |
| Руководитель IT-отдела | РуководительITОтдела |
| Ответственный за оборудование | ОтветственныйЗаОборудование |
| Администратор системы | АдминистраторСистемы |

Роли будут влиять на доступ к следующим объектам:

- документ «ITЗаявка»;
- справочник «Сотрудники»;
- справочник «КатегорииЗаявок»;
- справочник «Оборудование»;
- регистр сведений «ИсторияИзмененияЗаявок»;
- регистр сведений «ПравилаSLA»;
- регистр сведений «НарушенияSLA»;
- отчёты по заявкам;
- отчёты по оборудованию.

## 11. Вывод

В системе «1С Service Desk» выделены пять основных ролей: сотрудник, IT-специалист, руководитель IT-отдела, ответственный за оборудование и администратор системы.

Разграничение доступа необходимо для защиты данных, корректного распределения ответственности и формирования удобного интерфейса для каждой категории пользователей.

Описание ролей является основой для дальнейшего проектирования функциональных требований, use case диаграммы, тест-кейсов и настройки прав доступа в 1С.
