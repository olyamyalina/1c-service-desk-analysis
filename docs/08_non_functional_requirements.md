# 08. Нефункциональные требования

## 1. Назначение раздела

Данный раздел содержит нефункциональные требования к системе «1С Service Desk».

Нефункциональные требования описывают не отдельные функции системы, а качественные характеристики её работы: безопасность, производительность, надёжность, удобство использования, доступность, журналирование, хранение данных и требования к разграничению доступа.

Раздел используется при проектировании архитектуры решения, интерфейсов, прав доступа, отчётности, тест-кейсов и будущей реализации прототипа в 1С.

## 2. Отличие нефункциональных требований от функциональных

Функциональные требования описывают, что система должна делать.

Пример функционального требования:

> Система должна позволять сотруднику создать IT-заявку.

Нефункциональные требования описывают, как система должна работать.

Пример нефункционального требования:

> Форма создания IT-заявки должна открываться не дольше 3 секунд при нормальной нагрузке.

Таким образом, функциональные требования определяют возможности системы, а нефункциональные требования определяют качество реализации этих возможностей.

## 3. Область действия нефункциональных требований

Нефункциональные требования относятся к следующим аспектам системы:

1. производительность;
2. безопасность;
3. разграничение доступа;
4. удобство использования;
5. надёжность;
6. доступность;
7. хранение данных;
8. журналирование действий;
9. масштабируемость;
10. сопровождаемость;
11. требования к отчётности;
12. требования к интерфейсу.

## 4. Приоритеты нефункциональных требований

Для требований используются следующие приоритеты:

| Приоритет | Значение |
|---|---|
| Must | обязательное требование для MVP |
| Should | важное требование для расширенной версии |
| Could | дополнительное требование, которое можно реализовать при дальнейшем развитии проекта |

## 18. Связь нефункциональных требований с проектом 1С

Нефункциональные требования будут учитываться при проектировании объектов 1С, ролей доступа, форм, отчётов и регистров.

Примеры связи нефункциональных требований с 1С:

| Нефункциональное требование | Реализация в 1С |
|---|---|
| Разграничение доступа по ролям | роли пользователей 1С |
| Хранение истории изменений | регистр сведений «ИсторияИзмененияЗаявок» |
| Контроль нарушений SLA | регистр сведений «НарушенияSLA» |
| Фильтрация заявок | формы списков и отборы |
| Отчёты с учётом прав | отчёты с ограничением доступа |
| Настройка справочников | справочники категорий, приоритетов и оборудования |
| Хранение правил SLA | регистр сведений «ПравилаSLA» |
| Визуальное выделение просрочек | условное оформление в формах списков |

## 19. Вывод

Нефункциональные требования определяют качественные характеристики системы «1С Service Desk».

Они описывают, как система должна работать с точки зрения безопасности, производительности, удобства, надёжности, хранения данных, журналирования, интерфейса и отчётности.

Данный раздел дополняет функциональные требования и является основой для дальнейшего проектирования бизнес-правил, ER-модели, объектов 1С и тест-кейсов.
