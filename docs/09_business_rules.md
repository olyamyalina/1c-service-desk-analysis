# 09. Бизнес-правила

## 1. Назначение раздела

Данный раздел содержит бизнес-правила системы «1С Service Desk».

Бизнес-правила описывают условия, ограничения и логику выполнения процесса обработки IT-заявок. Они определяют, при каких условиях заявка может менять статус, кто имеет право выполнять определённые действия, как рассчитывается SLA, как фиксируются нарушения сроков и какие данные являются обязательными.

Раздел используется при проектировании функциональной логики системы, ER-модели, объектов 1С, тест-кейсов и сценариев проверки.

## 2. Область действия бизнес-правил

Бизнес-правила относятся к следующим блокам системы:

1. создание IT-заявки;
2. назначение исполнителя;
3. жизненный цикл статусов заявки;
4. обработка заявки IT-специалистом;
5. запрос уточнений;
6. проверка результата сотрудником;
7. контроль SLA;
8. связь заявки с оборудованием;
9. история изменений;
10. права доступа;
11. отчётность;
12. администрирование справочников.

## 3. Правила создания IT-заявки

| ID | Бизнес-правило |
|---|---|
| BR-001 | IT-заявка может быть создана только зарегистрированным пользователем системы. |
| BR-002 | При создании заявки должен быть указан заявитель. |
| BR-003 | При создании заявки должна быть указана категория обращения. |
| BR-004 | При создании заявки должно быть заполнено описание проблемы. |
| BR-005 | При создании заявки должен быть указан приоритет обращения. |
| BR-006 | Если заявка связана с конкретным устройством, в заявке должно быть указано оборудование. |
| BR-007 | Новая заявка автоматически получает уникальный номер. |
| BR-008 | Новая заявка автоматически получает дату и время создания. |
| BR-009 | Новая заявка автоматически получает статус «Новая». |
| BR-010 | Заявка не может быть сохранена, если не заполнены обязательные поля: заявитель, категория, описание проблемы и приоритет. |

## 4. Правила назначения исполнителя

| ID | Бизнес-правило |
|---|---|
| BR-011 | Заявка в статусе «Новая» должна быть назначена исполнителю перед началом обработки. |
| BR-012 | Исполнителем заявки может быть только пользователь с ролью «IT-специалист». |
| BR-013 | Руководитель IT-отдела имеет право изменить исполнителя заявки. |
| BR-014 | После назначения исполнителя заявка переводится в статус «Назначена». |
| BR-015 | IT-специалист видит в рабочем списке заявки, назначенные ему. |
| BR-016 | Заявка не может перейти в статус «В работе», если исполнитель не назначен. |
| BR-017 | Изменение исполнителя должно фиксироваться в истории заявки. |

## 5. Правила жизненного цикла статусов заявки

В системе используется следующий жизненный цикл заявки:

```text
Новая
↓
Назначена
↓
В работе
↓
Ожидает уточнения
↓
В работе
↓
Решена
↓
Закрыта

```

Также возможны дополнительные статусы:

```text
Отменена
Просрочена
Ожидает оборудование или запчасть
```

| ID | Бизнес-правило |
|---|---|
| BR-018 | После создания заявка получает статус «Новая». |
| BR-019 | После назначения исполнителя заявка получает статус «Назначена». |
| BR-020 | После взятия заявки исполнителем в работу заявка получает статус «В работе». |
| BR-021 | Если исполнителю недостаточно информации, заявка переводится в статус «Ожидает уточнения». |
| BR-022 | После предоставления уточнения заявка возвращается в статус «В работе». |
| BR-023 | После указания результата выполнения заявка переводится в статус «Решена». |
| BR-024 | После подтверждения результата сотрудником заявка переводится в статус «Закрыта». |
| BR-025 | Если сотрудник указал, что проблема не решена, заявка возвращается в статус «В работе». |
| BR-026 | Закрытая заявка не может быть изменена обычным пользователем. |
| BR-027 | Переход заявки в новый статус должен фиксироваться в истории изменений. |
| BR-028 | Система не должна позволять перейти к статусу, который нарушает жизненный цикл заявки. |

## 6. Правила обработки заявки IT-специалистом

| ID | Бизнес-правило |
|---|---|
| BR-029 | IT-специалист может взять в работу только назначенную ему заявку. |
| BR-030 | Факт взятия заявки в работу считается реакцией исполнителя. |
| BR-031 | При взятии заявки в работу система фиксирует дату и время реакции. |
| BR-032 | IT-специалист может добавить комментарий к заявке во время обработки. |
| BR-033 | IT-специалист может запросить уточнение, если информации по заявке недостаточно. |
| BR-034 | IT-специалист должен указать результат выполнения перед переводом заявки в статус «Решена». |
| BR-035 | Заявка не может быть переведена в статус «Решена» без результата выполнения. |
| BR-036 | IT-специалист не может закрыть заявку от имени сотрудника без отдельного права. |
| BR-037 | Если заявка возвращена в работу, IT-специалист должен повторно обработать обращение. |

## 7. Правила запроса уточнения

| ID | Бизнес-правило |
|---|---|
| BR-038 | Уточнение может быть запрошено только по заявке, находящейся в статусе «В работе». |
| BR-039 | При запросе уточнения заявка переводится в статус «Ожидает уточнения». |
| BR-040 | При запросе уточнения IT-специалист должен указать текст вопроса или комментарий. |
| BR-041 | Сотрудник может предоставить уточнение только по своей заявке. |
| BR-042 | После предоставления уточнения оно сохраняется в карточке заявки. |
| BR-043 | После предоставления уточнения заявка возвращается в статус «В работе». |
| BR-044 | Факт предоставления уточнения должен фиксироваться в истории заявки. |

## 8. Правила проверки результата и закрытия заявки

| ID | Бизнес-правило |
|---|---|
| BR-045 | После перевода заявки в статус «Решена» сотрудник должен проверить результат выполнения. |
| BR-046 | Заявку может подтвердить и закрыть сотрудник, который является заявителем. |
| BR-047 | Если сотрудник подтверждает решение проблемы, заявка переводится в статус «Закрыта». |
| BR-048 | Если сотрудник указывает, что проблема не решена, заявка возвращается в статус «В работе». |
| BR-049 | При возврате заявки в работу сотрудник должен указать причину возврата. |
| BR-050 | Закрытая заявка сохраняется в системе для истории и отчётности. |
| BR-051 | Закрытая заявка не должна удаляться из системы обычным пользователем. |

## 9. Правила контроля SLA

| ID | Бизнес-правило |
|---|---|
| BR-052 | Для каждой заявки должен рассчитываться срок реакции. |
| BR-053 | Для каждой заявки должен рассчитываться срок решения. |
| BR-054 | Срок реакции и срок решения рассчитываются на основании приоритета заявки. |
| BR-055 | Срок реакции считается выполненным, когда IT-специалист берёт заявку в работу. |
| BR-056 | Срок решения считается выполненным, когда заявка переводится в статус «Решена». |
| BR-057 | Если исполнитель не взял заявку в работу до истечения срока реакции, система фиксирует нарушение SLA реакции. |
| BR-058 | Если заявка не переведена в статус «Решена» до истечения срока решения, система фиксирует нарушение SLA решения. |
| BR-059 | Нарушение SLA не должно останавливать обработку заявки. |
| BR-060 | При нарушении SLA система должна уведомить руководителя IT-отдела. |
| BR-061 | Руководитель IT-отдела должен видеть просроченные заявки в отчёте. |
| BR-062 | Нарушение SLA должно сохраняться для последующей отчётности. |
| BR-063 | Одна заявка может иметь нарушение SLA реакции, нарушение SLA решения или оба нарушения одновременно. |

## 10. Правила приоритетов и сроков SLA

Для проекта используются следующие базовые правила SLA:

| Приоритет | Срок реакции | Срок решения |
|---|---:|---:|
| Критический | 15 минут | 4 часа |
| Высокий | 1 час | 8 часов |
| Средний | 4 часа | 2 рабочих дня |
| Низкий | 1 рабочий день | 5 рабочих дней |

| ID | Бизнес-правило |
|---|---|
| BR-064 | Каждому приоритету должен соответствовать срок реакции. |
| BR-065 | Каждому приоритету должен соответствовать срок решения. |
| BR-066 | Критические заявки должны иметь минимальный срок реакции и решения. |
| BR-067 | Правила SLA могут изменяться администратором системы. |
| BR-068 | Пользователи без административных прав не могут изменять правила SLA. |
| BR-069 | Если правила SLA изменены, новые правила применяются к новым заявкам. |
| BR-070 | Для уже созданных заявок сроки SLA сохраняются такими, какими они были рассчитаны при создании заявки. |

## 11. Правила связи заявки с оборудованием

| ID | Бизнес-правило |
|---|---|
| BR-071 | Заявка может быть связана с конкретным оборудованием. |
| BR-072 | Связь с оборудованием обязательна, если категория заявки относится к оборудованию. |
| BR-073 | Одно оборудование может быть связано с несколькими заявками за период эксплуатации. |
| BR-074 | Одна заявка может быть связана с одним основным устройством в рамках MVP. |
| BR-075 | Ответственный за оборудование может изменять карточку оборудования. |
| BR-076 | IT-специалист может указать оборудование в заявке, если оно относится к проблеме. |
| BR-077 | Сотрудник может видеть оборудование, закреплённое за ним. |
| BR-078 | История заявок по оборудованию должна быть доступна ответственному за оборудование и руководителю IT-отдела. |

## 12. Правила истории изменений

| ID | Бизнес-правило |
|---|---|
| BR-079 | Каждое изменение статуса заявки должно фиксироваться в истории. |
| BR-080 | В истории изменения статуса должны сохраняться дата и время изменения. |
| BR-081 | В истории изменения статуса должен сохраняться пользователь, выполнивший изменение. |
| BR-082 | В истории изменения статуса должен сохраняться старый статус. |
| BR-083 | В истории изменения статуса должен сохраняться новый статус. |
| BR-084 | В истории изменения статуса должен сохраняться комментарий, если он был указан. |
| BR-085 | История изменения статусов не должна редактироваться обычными пользователями. |
| BR-086 | История изменения статусов не должна удаляться при закрытии заявки. |

## 13. Правила доступа

| ID | Бизнес-правило |
|---|---|
| BR-087 | Сотрудник может просматривать только свои заявки. |
| BR-088 | IT-специалист может просматривать назначенные ему заявки. |
| BR-089 | Руководитель IT-отдела может просматривать все заявки. |
| BR-090 | Ответственный за оборудование может просматривать карточки оборудования и заявки, связанные с оборудованием. |
| BR-091 | Администратор системы может управлять пользователями, ролями, справочниками и правилами SLA. |
| BR-092 | Пользователь без соответствующей роли не может изменять карточки оборудования. |
| BR-093 | Пользователь без соответствующей роли не может просматривать управленческие отчёты. |
| BR-094 | Пользователь без административных прав не может изменять роли пользователей. |
| BR-095 | Пользователь без административных прав не может изменять настройки SLA. |

## 14. Правила отчётности

| ID | Бизнес-правило |
|---|---|
| BR-096 | Отчёты должны формироваться на основании данных, сохранённых в системе. |
| BR-097 | Отчёт «Заявки по статусам» должен учитывать текущий статус заявки. |
| BR-098 | Отчёт «Просроченные заявки» должен учитывать нарушения SLA реакции и SLA решения. |
| BR-099 | Отчёт «Нарушения SLA» должен показывать тип нарушения: реакция, решение или оба нарушения. |
| BR-100 | Отчёт «Загрузка IT-специалистов» должен учитывать количество заявок, назначенных каждому исполнителю. |
| BR-101 | Отчёты должны учитывать права доступа пользователя. |
| BR-102 | Сотрудник не должен видеть управленческие отчёты. |
| BR-103 | Руководитель IT-отдела должен видеть отчёты по всем заявкам. |
| BR-104 | Ответственный за оборудование должен видеть отчёты по оборудованию. |

| BR-107 | Администратор системы может управлять правилами SLA. |

## 17. Связь бизнес-правил с объектами 1С

## 18. Вывод

Бизнес-правила определяют ограничения и условия работы системы «1С Service Desk».

Они уточняют функциональные требования и описывают, как именно должна работать логика создания, обработки, контроля и закрытия IT-заявок.

Данный раздел является основой для проектирования ER-модели, объектов 1С, проверок в системе и тест-кейсов.
