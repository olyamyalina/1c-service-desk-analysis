# 15. HTTP API

## 1. Назначение

HTTP-сервис `ServiceDeskAPI` предоставляет доступ к заявкам Service Desk через JSON.

Базовый адрес локальной публикации:

```text
http://localhost/ServiceDesk/hs/api/v1
```

Для опубликованной информационной базы используется Basic-аутентификация пользователя 1С. Заявитель при создании заявки определяется по текущему авторизованному пользователю и его связи с активным элементом справочника «Сотрудники».

## 2. Реализованные методы

| Метод | Адрес | Назначение |
|---|---|---|
| `GET` | `/ping` | Проверка доступности HTTP-сервиса |
| `GET` | `/tickets/{number}` | Получение заявки по номеру |
| `POST` | `/tickets` | Создание новой заявки |

Получение списка заявок через `GET /tickets` пока не зафиксировано как реализованное.

## 3. Создание заявки

### 3.1. Входные поля

| Поле | Тип | Обязательность | Описание |
|---|---|---|---|
| `categoryCode` | Строка | Обязательное | Код элемента справочника категорий |
| `priority` | Строка | Обязательное | Наименование приоритета: `Низкий`, `Средний` или `Высокий` |
| `description` | Строка | Обязательное | Описание проблемы |
| `equipmentCode` | Строка | Необязательное | Код оборудования; становится обязательным, если выбранная категория требует оборудование |

Поле `applicantCode` не передаётся. Заявитель определяется сервером по пользователю информационной базы.

### 3.2. Пример запроса

Проверенный запрос, в результате которого создана заявка №000000018:

```json
{
  "categoryCode": "000000005",
  "priority": "Средний",
  "description": "Тестовая заявка, созданная через HTTP API"
}
```

Пример PowerShell:

```powershell
$body = @{
    categoryCode = "000000005"
    priority = "Средний"
    description = "Тестовая заявка, созданная через HTTP API"
} | ConvertTo-Json -Compress

$bodyBytes = [System.Text.Encoding]::UTF8.GetBytes($body)

$response = Invoke-RestMethod `
    -Uri "http://localhost/ServiceDesk/hs/api/v1/tickets" `
    -Method Post `
    -Headers $headers `
    -ContentType "application/json; charset=utf-8" `
    -Body $bodyBytes
```

Переменная `$headers` должна содержать заголовок Basic-аутентификации. Учётные данные в репозитории не сохраняются.

## 4. Успешный ответ

При успешном создании сервер возвращает HTTP `201 Created`, заголовок `Location` и объект JSON формата `success + ticket`.

Фактически полученный ответ для заявки №000000018:

```json
{
  "success": true,
  "ticket": {
    "number": "000000018",
    "date": "2026-09-07T02:15:56",
    "applicant": "Иванова Анна Сергеевна",
    "category": "Консультация",
    "priority": "Средний",
    "status": "Новая",
    "equipment": "",
    "reactionDeadline": "2026-09-07T06:15:56",
    "solutionDeadline": "2026-09-07T18:15:56"
  }
}
```

Даты передаются в формате `yyyy-MM-dd'T'HH:mm:ss`.

## 5. Ошибки приложения

Ошибки, сформированные модулем HTTP-сервиса, имеют единый JSON-формат:

```json
{
  "success": false,
  "error": "Текст ошибки"
}
```

Ошибки аутентификации, сформированные до вызова обработчика 1С, могут возвращаться веб-сервером не в этом JSON-формате.

## 6. Состояние проверки

| Сценарий | Состояние |
|---|---|
| Успешное создание заявки | Проверено: создана заявка №000000018 |
| Пустое тело запроса | Проверено: HTTP 400, «Тело запроса не заполнено.» |
| Неизвестная категория | Требуется проверить |
| Пользователь 1С не связан с активным сотрудником | Требуется проверить |
| Некорректный JSON | Требуется проверить |
| Неизвестный приоритет | Требуется проверить |
| Не указано обязательное оборудование | Требуется проверить |
| Несуществующий номер заявки | Требуется проверить |

## 7. Ограничения текущей публикации

Адрес `localhost` и HTTP без TLS относятся к локальной учебной среде. Перед сетевой публикацией необходимо настроить HTTPS и пароли пользователей.
