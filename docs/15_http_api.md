# 15. HTTP API

## 1. Назначение

HTTP-сервис `ServiceDeskAPI` предоставляет JSON-интерфейс для проверки доступности сервиса, создания заявки и получения заявки по номеру.

Базовый адрес локальной учебной публикации:

```text
http://localhost/ServiceDesk/hs/api/v1
```

Публикация использует аутентификацию пользователя информационной базы. При создании заявки заявитель определяется сервером по точному совпадению имени пользователя ИБ с реквизитом `ИмяПользователяИБ` одного активного элемента справочника `Сотрудники`.

## 2. Методы

| Метод | Адрес | Назначение | Реализован в исходниках |
|---|---|---|---|
| `GET` | `/ping` | Проверка доступности сервиса | Да |
| `GET` | `/tickets/{number}` | Получение непомеченной на удаление заявки по номеру | Да |
| `POST` | `/tickets` | Создание новой заявки от имени текущего пользователя | Да |

`GET /tickets`, изменение и удаление заявок в текущей версии отсутствуют.

## 3. Общий формат ответа

Успешные операции с заявкой возвращают объект `success + ticket`:

```json
{
  "success": true,
  "ticket": {}
}
```

Ошибки, сформированные обработчиком 1С, возвращаются в формате:

```json
{
  "success": false,
  "error": "Текст ошибки"
}
```

Все обработчики устанавливают `Content-Type: application/json; charset=utf-8`. Даты преобразуются в строки формата `yyyy-MM-dd'T'HH:mm:ss`; незаполненные даты и ссылки представлены пустой строкой.

Ошибки веб-сервера или аутентификации, возникшие до вызова обработчика, могут иметь другой формат.

## 4. `GET /ping`

Запрос:

```http
GET /ServiceDesk/hs/api/v1/ping
```

Ответ HTTP 200:

```json
{
  "status": "ok",
  "service": "ServiceDeskAPI",
  "message": "Service Desk API is available"
}
```

## 5. `POST /tickets`

### 5.1. Поля запроса

| Поле | Тип | Обязательность | Обработка |
|---|---|---|---|
| `categoryCode` | Строка | Обязательное | Категория ищется по коду |
| `priority` | Строка | Обязательное | Приоритет ищется по наименованию |
| `description` | Строка | Обязательное | После удаления пробелов по краям строка не должна быть пустой |
| `equipmentCode` | Строка | Условно обязательное | Оборудование ищется по коду; поле обязательно для категории с признаком `ТребуетОборудование` |

Поле заявителя не принимается: клиент не может создать заявку от имени произвольного сотрудника.

Код ищет приоритет в справочнике по переданной строке. Сообщение для неизвестного значения перечисляет `Низкий`, `Средний` и `Высокий`, поэтому эти элементы должны быть созданы в справочнике, если их использует клиент.

### 5.2. Пример запроса

Проверенный запрос, создавший заявку №000000018:

```json
{
  "categoryCode": "000000005",
  "priority": "Средний",
  "description": "Тестовая заявка, созданная через HTTP API"
}
```

Пример PowerShell:

```powershell
$body = @{
    categoryCode = "000000005"
    priority = "Средний"
    description = "Тестовая заявка, созданная через HTTP API"
} | ConvertTo-Json -Compress

$bodyBytes = [System.Text.Encoding]::UTF8.GetBytes($body)

$response = Invoke-RestMethod `
    -Uri "http://localhost/ServiceDesk/hs/api/v1/tickets" `
    -Method Post `
    -Headers $headers `
    -ContentType "application/json; charset=utf-8" `
    -Body $bodyBytes
```

Переменная `$headers` должна содержать заголовок аутентификации. Учётные данные в репозитории не сохраняются.

### 5.3. Успешный ответ

При успешном создании сервер возвращает HTTP 201 и заголовок:

```text
Location: /ServiceDesk/hs/api/v1/tickets/{number}
```

Фактически полученный ответ для заявки №000000018:

```json
{
  "success": true,
  "ticket": {
    "number": "000000018",
    "date": "2026-09-07T02:15:56",
    "applicant": "Иванова Анна Сергеевна",
    "category": "Консультация",
    "priority": "Средний",
    "status": "Новая",
    "equipment": "",
    "reactionDeadline": "2026-09-07T06:15:56",
    "solutionDeadline": "2026-09-07T18:15:56"
  }
}
```

### 5.4. Ошибки `POST`

| Условие | Код | Сообщение обработчика |
|---|---:|---|
| Пустое тело | 400 | `Тело запроса не заполнено.` |
| Некорректный JSON | 400 | `Передан некорректный JSON.` |
| Корень JSON не является объектом | 400 | `В теле запроса должен находиться объект JSON.` |
| Нет `categoryCode` | 400 | `Не указано поле categoryCode.` |
| Пустой `categoryCode` | 400 | `Поле categoryCode не должно быть пустым.` |
| Нет `priority` | 400 | `Не указано поле priority.` |
| Пустой `priority` | 400 | `Поле priority не должно быть пустым.` |
| Нет `description` | 400 | `Не указано поле description.` |
| Пустое описание | 400 | `Описание проблемы не должно быть пустым.` |
| Категория не найдена | 400 | `Категория с кодом ... не найдена.` |
| Приоритет не найден | 400 | `Неизвестный приоритет. Допустимые значения: Низкий, Средний, Высокий.` |
| Оборудование не найдено | 400 | `Оборудование с кодом ... не найдено.` |
| Для категории не передано оборудование | 400 | `Для выбранной категории необходимо указать equipmentCode.` |
| Пользователь не связан с активным сотрудником | 403 | `Текущий пользователь ИБ не связан с активным сотрудником.` |
| Ошибка записи документа | 500 | `Не удалось создать заявку. ...` |

Запись документа дополнительно запускает проверки модуля `ITЗаявка`, включая правило SLA и допустимость выбранного оборудования. Такая ошибка возвращается как HTTP 500 вместе с описанием исключения 1С.

## 6. `GET /tickets/{number}`

Пример запроса:

```http
GET /ServiceDesk/hs/api/v1/tickets/000000018
```

При успехе обработчик возвращает HTTP 200 и поля:

```json
{
  "success": true,
  "ticket": {
    "number": "000000018",
    "date": "2026-09-07T02:15:56",
    "applicant": "Иванова Анна Сергеевна",
    "category": "Консультация",
    "priority": "Средний",
    "status": "Новая",
    "executor": "",
    "description": "Тестовая заявка, созданная через HTTP API",
    "equipment": "",
    "reactionDeadline": "2026-09-07T06:15:56",
    "solutionDeadline": "2026-09-07T18:15:56"
  }
}
```

Этот объект показывает контракт, сформированный текущим кодом для данных ранее созданной заявки. Фактический успешный вызов `GET` ещё не отмечен как проверенный.

Ошибки:

| Условие | Код | Сообщение обработчика |
|---|---:|---|
| Номер отсутствует или пуст | 400 | `Не указан номер заявки.` |
| Заявка не найдена | 404 | `Заявка с номером ... не найдена.` |
| Ошибка запроса к базе | 500 | `Не удалось получить данные заявки.` |

## 7. Состояние ручной проверки

| Сценарий | Состояние |
|---|---|
| Успешный `POST /tickets` | Проверено: создана заявка №000000018 |
| Пустое тело `POST /tickets` | Проверено: HTTP 400 |
| `GET /ping` | Требуется зафиксировать результат |
| Успешный `GET /tickets/{number}` | Требуется проверить |
| Несуществующий номер заявки | Требуется проверить |
| Некорректный JSON | Требуется проверить |
| Корень JSON не является объектом | Требуется проверить |
| Отсутствующие и пустые обязательные поля | Требуется проверить |
| Неизвестные категория, приоритет и оборудование | Требуется проверить |
| Категория с обязательным оборудованием | Требуется проверить |
| Пользователь без связанного активного сотрудника | Требуется проверить |

## 8. Ограничения публикации

Адрес `localhost` и HTTP без TLS относятся к локальной учебной среде. Перед сетевой публикацией необходимо настроить HTTPS, безопасное хранение учётных данных и проверить доступ каждой роли к HTTP-методам.
