# 1С Service Desk

Учебно-портфельная конфигурация на платформе «1С:Предприятие» для регистрации и обработки внутренних IT-заявок, контроля SLA, работы с комментариями и уведомлениями, а также учёта выдачи и ремонта оборудования.

В репозитории находятся аналитическая документация, диаграммы и выгрузка исходников конфигурации в XML-файлы и модули BSL.

## Что реализовано

| Блок | Текущая реализация |
|---|---|
| IT-заявки | Создание заявки, автоматическое определение заявителя, начальный статус «Новая», назначение исполнителя, проверки заполнения и управляемый жизненный цикл |
| SLA | Выбор правила по приоритету и дате заявки, расчёт сроков реакции и решения, ручная и регламентная проверка нарушений |
| История | Регистрация переходов статусов и изменений исполнителя |
| Комментарии | Обычные комментарии, запросы уточнения, ответы сотрудника, причины возврата и служебные заметки; поддерживается аннулирование |
| Уведомления | Уведомления заявителя, исполнителя, руководителей и ответственных за оборудование; отметки показа, прочтения и обработки |
| Оборудование | Карточки оборудования, история состояний, выдача сотруднику и ремонт с фиксацией результата |
| Отчёты | «Анализ заявок» и «Контроль SLA» на системе компоновки данных |
| HTTP API | `GET /ping`, `GET /tickets/{number}` и `POST /tickets` с JSON-ответами |
| Доступ | Базовая и пять функциональных ролей, проверки действий в коде и отборы данных в формах списков |

## Жизненный цикл заявки

Поддерживаются статусы:

`Новая` → `Назначена` → `В работе` → `Решена` → `Закрыта`.

Дополнительные ветки:

- из «В работе» — в «Ожидает уточнения», «Ожидает оборудование» или «Отменена»;
- из состояний ожидания — обратно в «В работе» или в «Отменена»;
- из «Решена» — в «Закрыта» или обратно в «В работе»;
- «Закрыта» и «Отменена» являются конечными состояниями.

Для переходов «В работе» → «Ожидает уточнения», «Ожидает уточнения» → «В работе» и «Решена» → «В работе» требуется актуальный комментарий соответствующего типа.

## SLA

Правило SLA выбирается из периодического регистра `ПравилаSLA` по приоритету на дату создания заявки. Сроки рассчитываются в календарных часах:

```text
Срок реакции = Дата заявки + Срок реакции, ч × 3600 секунд
Срок решения = Дата заявки + Срок решения, ч × 3600 секунд
```

Фактическая реакция фиксируется при первом переходе «Назначена» → «В работе», фактическое решение — при переходе «В работе» → «Решена». Регламентное задание `ПроверкаНарушенийSLA` запускает проверку каждые 300 секунд; ту же проверку можно вызвать вручную из списка нарушений.

## Оборудование

Операционное состояние оборудования определяется по последней записи регистра `ИсторияСостоянийОборудования`. При отсутствии записей оборудование считается находящимся на складе.

Реализованы состояния `НаСкладе`, `Используется`, `ВРемонте` и `Списано`. Значение `Списано` используется как допустимый результат завершённого ремонта: документ записывает выбранное состояние в историю и снимает закрепление с сотрудника. Чтобы после списания продолжить заявку из статуса «Ожидает оборудование», по этой заявке необходимо оформить выдачу замены — проверка возобновления ожидает завершённую операцию с оборудованием в состоянии `Используется`.

## Загрузка и запуск

Конфигурация имеет режим совместимости `Version8_3_27`. Порядок создания информационной базы, загрузки каталога `src`, первичного заполнения данных и настройки пользователей приведён в [инструкции по загрузке](docs/16_import_instructions.md).

Бинарные выгрузки `.dt` и `.cf`, пользовательские базы, журналы и учётные данные в репозиторий не включаются.

## Состояние проверки

Исходники и XML-файлы находятся в репозитории. Успешный `POST /tickets` и ошибка для пустого тела запроса проверены вручную; остальные проверки сведены в [тестовые сценарии](docs/14_test_scenarios.md) и не помечаются как пройденные без фактического запуска.

Известные ограничения текущей версии перечислены в [границах проекта](docs/13_project_scope.md).
